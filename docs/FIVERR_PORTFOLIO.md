**Project description**

```text
I built a reproducible ETL recovery lab to demonstrate how I diagnose, fix and validate broken data pipelines using Python, PySpark, SQL and pytest.

The defective pipeline fails after source columns are renamed, raises numeric conversion errors, multiplies rows through a historical customer join and duplicates output when rerun.

I reproduced the actual Spark errors, profiled the inputs and implemented explicit schema mappings, typed validation, deterministic version handling and quarantine with reason codes. The corrected pipeline validates the output before publishing one partition transactionally to SQLite.

Verified results: 17 source records were classified into 7 accepted lines, 8 rejected records, 1 duplicate and 1 superseded version. Line and aggregate totals reconciled exactly. Replaying the corrected pipeline left the published data unchanged; a stricter quality gate blocked publication and preserved the last valid partition. The legacy join produced 25 rows and accumulated 50 on replay.

The project includes a local monitor, saved JSON/CSV reports, execution logs and 39 automated tests. Independent portfolio project using synthetic data; no client outage or production recovery is claimed.
```
